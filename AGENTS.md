# AGENTS.md — Khamarvest Silage

Guidance for AI agents (and humans) working on this repo. Read this before editing.

## What this is

A static marketing + content site for **খামারভেস্ট সাইলেজ (Khamarvest Silage)** — corn/maize silage sold to Bangladeshi cattle farmers.

- Landing page: `index.html` (interactive silage calculator, WhatsApp-first ordering).
- Blog: `blog/*.html` plus root article `vutta-silage-prothombar-khawano-rules.html`.
- Domain: `https://silage.khamarvest.com`

## Tech / workflow

- Plain static HTML styled with Tailwind utility classes. **Tailwind is compiled, not loaded from the CDN**: `npm run build:css` scans every page (see `tailwind.config.js` > `content`) and writes the minified `css/site.css`, which every page links. Never add `<script src="https://cdn.tailwindcss.com">` back; the checker fails on it. The compiled `css/site.css` is committed because Cloudflare serves the repo as-is.
- **Fonts are self-hosted** in `fonts/` (Hind Siliguri 400-700, Noto Serif Bengali variable, Noto Sans Bengali variable) with `@font-face` rules in `css/fonts.css`, generated by `npm run fonts` (`scripts/fetch-fonts.mjs`). No page may reference `fonts.googleapis.com` or `fonts.gstatic.com`. Each page preloads its body font: blog/tools/area pages `/fonts/hind-siliguri-400-bengali.woff2`, the homepage `/fonts/noto-sans-bengali-300-700-bengali.woff2`. To add a weight or family: edit `CSS_URLS` in `scripts/fetch-fonts.mjs`, run `npm run fonts`, then `npm run build:css`.
- **After editing any class name in any page or generator template, run `npm run build:css`** (or `npm run build`), otherwise the new class has no CSS in production. `npm run verify` does this for you.
- `npm run build` regenerates the district pages, then `blog/index.html` + `sitemap.xml`, then `css/site.css`. Individual steps are `npm run build:areas`, `npm run build:blog` and `npm run build:css`.
- **`npm run check` validates the whole site against the rules in this file** (`scripts/check-site.mjs`): title suffix, meta description, robots, canonical (present, extensionless, matches the file path, no duplicates), the four required Open Graph tags, `og:url` matching canonical, valid JSON-LD with a well-formed `datePublished` and the correct author/publisher, brand mentioned at least twice in the article body, `/js/ga.js` present, internal links that actually resolve, no `.html` internal links, optimized images only, and no em/en dashes or Devanagari digits. `npm run verify` runs the build then the check.
- **Run `npm run verify` before every deploy.** It exits non-zero on errors, so it is safe to wire into CI. Warnings (for example an article with no `FAQPage` schema) do not fail the run.
- When adding a rule to this file, add the matching assertion to `scripts/check-site.mjs`, otherwise the rule will quietly rot.
- **IndexNow (Bing/ChatGPT indexing):** `.github/workflows/indexnow.yml` runs on every push to `main`, waits for the Cloudflare deploy, then `scripts/indexnow.mjs` submits the changed public URLs (and `llms.txt` / `llms-full.txt`) to `api.indexnow.org`. Bing's index is what ChatGPT search reads, so a new guide is citable within minutes. The key is public by design and lives in two places that must match: `INDEXNOW_KEY` in the script and the `<key>.txt` file at the repo root (the checker asserts this). Google ignores IndexNow; it reads `sitemap.xml`. Dry run locally: `npm run indexnow:dry`.
- **Automation that runs without anyone's laptop** (all GitHub Actions, all opening issues rather than changing content):
  - `.github/workflows/watchdog.yml`, **daily**. Runs `npm run watch` (`scripts/watch-site.mjs`) against the **live** site, which is the half `npm run check` cannot see: every sitemap URL returns 200 and is indexable, `http://` still 301s to `https://`, the homepage title still carries the price and is under 80 chars, the Product schema still offers 10 and 500 BDT, `priceValidUntil` has not lapsed (warns 60 days out, because an expired offer makes Google drop the price from the result), and no guide has gone 12 months untouched. Opens one issue when something breaks and **closes it** when the site is green again. Run locally with `npm run watch`, or `SITE=http://localhost:8321 npm run watch`.
  - `.github/workflows/competitor-watch.yml`, **weekly**. Snapshots aksilage.com and prantorsilage.com into `scripts/competitor-snapshot.json` (committed, so the diff survives) and reports new or removed pages, homepage title changes, and the two that matter most: the day either starts **publishing a price**, and the day either **claims a lab analysis**. Both are currently "no", and both are advantages we hold.
  - `.github/workflows/season.yml`, **monthly**. Runs `scripts/season-calendar.mjs`, which works backwards from the Bangladeshi farming year and says which guides must be live and re-crawled *before* a season rather than during it. Qurbani dates are lunar and cannot be computed, so `QURBANI` in that script is a hand-maintained map; the script says so when it runs out of years. It publishes nothing: Google's scaled-content-abuse policy targets automated publishing, and this site's advantage is that every claim is sourced, so the last step stays human.
  - `scripts/social-posts.mjs` + `scripts/social-posts.json`, run by the monthly workflow and by `npm run social`. Produces ready-to-paste Bengali Facebook posts, one per guide, in the format DISTRIBUTION.md sets out: lead with the useful thing, mention the product once at the end as a fact. **Why this exists:** this market transacts on Facebook, not on websites. Rupai Silage has roughly 9,900 page followers and a website in maintenance mode; we have 33 sourced guides and a YouTube channel with one video and 36 views. The content advantage only becomes leads once it reaches the channel farmers actually use. Posts are picked season-first (the monsoon post in the monsoon, Qurbani within 20 weeks of Eid), then evergreen rotated by week of year. Adding a guide means adding a post here; the checker fails if any `slug` does not resolve, since a bad Facebook link is the worst possible first impression. Price comes from `product.json`, so `set-price` updates the posts too.

  Also missing on the profile: business hours, photos, and **any reviews at all**, which is the single strongest local trust signal. `npm run social:gbp` generates Google Post copy in the right shape (~1,500 char limit, one Learn-more button).
  On the site side the `LocalBusiness` schema now lists all 33 districts (it claimed 18 while 33 pages existed) and carries `openingHoursSpecification`. Hours are 24/7 (owner, 2026-09-29): the schema says 00:00-23:59 every day, and the copy says WhatsApp is answered দিনরাত. When the owner shares the GBP share-link, add it to `sameAs` next to Facebook and YouTube.
- **External link check:** `.github/workflows/link-check.yml` runs `scripts/check-external-links.mjs` on the 1st of every month and opens/updates a GitHub issue listing dead তথ্যসূত্র links. 403/405/429 are reported as bot-blocked, not dead. Run locally: `npm run check:links`. When a source dies, replace the citation, do not just delete it.
- **Favicon.** `favicon.svg` is the source; `npm run favicon` regenerates `favicon.ico` (a real ICO wrapping a 48px PNG) and the PNG sizes, and `npm run build:favicon` (part of `npm run build`) writes the `<link>` block into every page between `<!-- favicon:start -->` and `<!-- favicon:end -->`. **Never use a `data:` URI icon:** Google's favicon crawler cannot fetch one, and until 2026-09-17 only the homepage declared an icon, as a data URI, while `/favicon.ico` 404ed. That 404 was what Search Console's "Not found (404)" was reporting, and the effect was a generic globe beside every result in mobile search. The checker fails if the files are missing, if any page lacks the block, or if a data: URI icon reappears.
- **404 page:** `404.html` is served by Cloudflare for every unknown path (`wrangler.jsonc` > `assets.not_found_handling: "404-page"`). It is intentionally `noindex`, has no canonical and stays out of `sitemap.xml`, `feed.xml` and IndexNow. It must keep links back to `/`, `/blog/`, `/tools/` and `/area/`: the checker asserts all of this. Old `.html` links and typos land here, so a dead end there costs a real farmer.
- **Mobile order bar.** `npm run build:orderbar` (`scripts/order-bar.mjs`, part of `npm run build`, after the generators) writes a fixed bottom bar (price, "পণ্য হাতে পেয়ে টাকা", কল করুন, WhatsApp-এ অর্ডার) into every page between `<!-- order-bar:start -->` and `<!-- order-bar:end -->`. It is `md:hidden print:hidden`, so desktop and the print sheets are untouched. Skipped: `index.html` (own floating button), `tools/ration-generator.html` (own mobile result bar), `guide-book.html`. Why: a phone reader of a guide scrolled 11-13 screens to the first WhatsApp link, and `/blog/` had none. The checker fails on a page without it. Phone numbers for generators live in `scripts/contact.mjs`: WhatsApp `8801303438063`, and `CALL_TEL` `+8801334211984`, the number the homepage already says to call. The owner confirmed 2026-09-29 that 01334-211984 takes calls; change it there and run `npm run build` if that ever changes.
- **WhatsApp prefill.** A bare `wa.me` link opens an empty chat, and the owner cannot tell which page sent the lead (GA sees the click, not the order). `/js/ga.js` fills any `wa.me` link without `?text=` with the page's H1 plus "এলাকা: / বস্তা:" lines; the homepage does the same inline. District pages name the district and ask for upazila and bag count; calculators write their own message. Do not hand-write a generic `?text=` on new pages, leave the link bare and let the script name the page.
- **RSS feed:** `feed.xml` is regenerated by `npm run build:blog` (latest 25 guides). The homepage and `/blog/` both declare it with `<link rel="alternate" type="application/rss+xml">`. It is a machine-readable "what changed" endpoint for aggregators and AI crawlers, and a discovery path that does not wait on Google indexing.
- **Sitemap `lastmod` must be truthful.** Articles use their JSON-LD `dateModified` (falling back to `datePublished`); every other page uses its last git commit date. Never stamp the whole sitemap with today: crawlers learn the field is noise and stop using it to prioritise recrawls. The checker fails if all the dates are identical or any is in the future.
- Local preview: `node .claude/serve.js` → `http://localhost:8321` (serves directory index, e.g. `/blog/`).
- **Open issue (found 2026-09-15): `http://silage.khamarvest.com/` serves the whole site with a 200 and never redirects to HTTPS.** Every page therefore exists at two protocols. The canonical tags point at `https://`, so Google should consolidate, but it still wastes crawl budget and serves visitors over plain HTTP. The fix is a Cloudflare dashboard toggle, not a repo change: SSL/TLS > Edge Certificates > **Always Use HTTPS** (and optionally Enable HSTS). Workers Assets config cannot do a protocol redirect, so do not look for it in `wrangler.jsonc`.
- **Search Console is still unverified; Bing Webmaster Tools is verified** (the homepage carries `msvalidate.01`, which is why IndexNow submissions work). The homepage has no `google-site-verification` meta tag. Crawlability itself is fine, audited 2026-09-15: all 64 sitemap URLs return 200, none are noindex, robots.txt allows Googlebot, and Googlebot receives byte-identical HTML to a browser. Nothing in the repo is blocking Google; the property simply has never been claimed.
- Deploy: Cloudflare Workers Assets (`wrangler.jsonc`, `assets.directory = "."`). **Pushing to `main` auto-deploys** via the Cloudflare GitHub integration — no manual `wrangler deploy` needed.
- Do **NOT** set `assets.html_handling = "none"`: it also disables auto `index.html` serving, so `/` and `/blog/` return 404. The default serves `.html` at extensionless URLs (307 redirect) and resolves directory indexes.
- **URL convention (applied 2026-08-18): ALL canonicals, og:url, JSON-LD `mainEntityOfPage`, sitemap entries and internal links use the extensionless form** (`/blog/foo`, not `/blog/foo.html`). The `.html` form 307-redirects, which weakens Google indexing and breaks AI crawlers (ChatGPT/Perplexity citations). Never reintroduce `.html` URLs in published pages.
- **Responsive images.** `npm run images` (sharp, a devDependency) writes 480w/800w/1200w JPEG variants, plus WebP **only for images where WebP is smaller at every width** (on these grass-and-stalk field photos mozjpeg often wins: at WebP q78 every `<picture>` was serving the larger file). A JPEG-only image is normal, and the wrapper then emits only the JPEG source of every `img/*-1200.jpeg` / `*-1400.jpeg` into `img/`. `npm run build:images` (part of `npm run build`) then wraps every `<img src="/img/*.jpeg">` in a `<picture>` with both srcsets. It is idempotent: it unwraps its own output first, so re-running can never nest (an earlier version double-wrapped twelve files). `npm run images` is a manual step like `npm run fonts`, run it after adding an image. The homepage uses relative `img/` paths with hand-tuned `sizes` and an `image-set()` hero background, so the wrapper deliberately skips it. The checker fails on a `srcset` or CSS `url()` pointing at a file that does not exist, because a typo there falls back silently to the full-size image and every visitor pays for it.
- **Images in pages must use the optimized copies** (`img/*-1200.jpeg`, `img/*-1400.jpeg`, ~300-600 KB), never the raw `img/IMG_*.JPG.jpeg` originals (3-6 MB — kills Core Web Vitals on rural mobile). Make new optimized copies with `sips -Z 1200 --setProperty format jpeg --setProperty formatOptions 68 in.jpeg --out out.jpeg`.

## Single sources (read before editing any fact)

**`EDITING.md` is the owner-facing guide: every changeable fact, where it lives, and the one command that spreads it.** In short:
- **Business facts** (WhatsApp, call numbers, Facebook, YouTube, GA4 ID) live in `scripts/site.json`. `npm run build:facts` (`scripts/sync-facts.mjs`, first build step) compares it with `scripts/site.applied.json` and rewrites every format of a changed value across pages, generators, scripts, llms files and docs (tested round trip: 506 replacements in 102 files and back, byte-identical). The checker fails if the two files disagree or if any page carries a phone number not in `site.json`. `scripts/contact.mjs` reads `site.json`, so generators use it directly.
- **Price** lives in `scripts/product.json`, changed with `npm run set-price`. Prices are formatted by `money()` / `moneyEn()` (৮.৫০, BDT 8.50).
- **Price-dependent figures carry their formula**: `<!--=36*bag-->১৫,৩০০<!--/=-->` (`scripts/calc.mjs`, `npm run build:calc`). Names `price`, `bag`, `bagKg`, `prev`; filters `|round`, `|en`. Also wrap the price itself where it sits inside arithmetic or alone in a table cell, because `set-price` only recognises it next to "কেজি" or "বস্তা". Markers never go inside `<script>` (the checker fails that). A stale formula value fails the check. Proven end to end on 2026-09-30: a simulated 9 tk change needed no hand edits.
- **FAQ is written once, visibly**, between `<!-- faq:start -->` and `<!-- faq:end -->` as `<details><summary>…</summary><p>…</p></details>` (or `<h3>` + `<p>` pairs). `npm run build:faq` (`scripts/faq.mjs`) writes the FAQPage JSON-LD from it. Until 2026-09-30, 185 of 198 schema questions were not visible on their page, against Google's rule that FAQ markup must match visible content; the migration made all of them visible. District pages are exempt: their generator writes both from one template.
- **Year labels** ("© YYYY", "দাম (YYYY)") are set by `npm run build:year` (`scripts/year.mjs`), and `.github/workflows/new-year.yml` runs it on 1 January, commits, and opens an issue listing titles/sentences that still name last year.
- A price **increase** makes the check fail while the homepage still says "দাম কমেছে" / "টাকা কম".

## Brand / content rules (IMPORTANT)

- Brand names: **খামারভেস্ট সাইলেজ** (Bangla) and **Khamarvest Silage** (English). Brand entity is "খামারভেস্ট (Khamarvest)".
- Every blog article MUST mention the brand **naturally in the body text at least 2 times** — not only in `<title>`, meta, header, footer, or CTA boxes. Search engines and AI agents (AI Overviews, ChatGPT, Perplexity) read the *body*; the brand in the body is what makes them cite/associate the brand.
- Weave the brand into value (price, quality, delivery, usage). Never keyword-stuff.
- **NO em dashes (—) or en dashes (–) anywhere in published content** (body, titles, meta, JSON-LD, llms.txt, llms-full.txt). The owner considers them AI-sounding. Use a comma, a colon, or restructure the sentence; write number ranges with a plain hyphen (১৫-২৫).
- **The price lives in one place: `scripts/product.json`.** It is written in ~400 spots across ~80 files (page bodies, JSON-LD offers, three calculator constants, `llms.txt` and `llms-full.txt`, the area generator), so never change it by hand. Run `npm run set-price -- --per-kg 12 --bag 600` (add `--dry` to preview). The codemod rewrites every enumerated pattern and **reports anything it does not recognise instead of guessing**, which matters most for derived sums: "১৫০ টাকা (১৫ কেজি × ১০ টাকা)" has a total that has to be recomputed by a human. `npm run check` then fails on any page still showing a superseded price, so a half-finished change cannot ship. Two bugs found while building it, both worth knowing about if you extend the rules: a function replacer does not expand `$1`, and `৬০০ টাকা` is a substring of `৩,৬০০ টাকা`, so every bare-number rule carries a `(?<![০-৯,])` guard.
- **On price history:** show only the current price everywhere, because a stale number means a farmer is quoted one price and charged another. When the price does change, `set-price` records the old one in `product.json > history`, and it is worth adding one line to `/blog/vutta-silage-dam-koto-kothay-kinben` saying what it was and why it moved. An explanation earns more trust from a farmer who remembers the old price than a silently updated number.
- **Lessons from the 10 → 8.50 change (2026-09-30), now fixed in the tooling:** `set-price` did not know the homepage's `PRICE_PER_BAG` constant (the calculator kept charging 500 a bag) and did not read `scripts/social-posts.json`; its bag rule also rewrote a transport share ("২০ বস্তা ... পরিবহন ২,০০০ ÷ ৪ = ৫০০ টাকা") into the new bag price. All three are fixed, and the bag rule now needs "বস্তা" nearby with no "পরিবহন" in between. The checker parsed prices as integers (it read `PRICE = 8.5` as 8). **Derived sums are the real work of a price change:** `set-price` only reports sentences that still contain the old number, so a total written on its own ("৩৬ বস্তা = ১৮,০০০ টাকা") is invisible to it. After every change, sweep for the old per-day and per-month figures (per cow 20 kg, per steer 15 kg, ×30 days, ×12 or ×9 bags) and the dry-matter cost (silage price ÷ 0.30).
- **The previous price was 12 tk/kg, 600 tk/bag** (owner, 2026-09-30), recorded in `product.json > history` with `until: 2025-12-31` (start date not recorded). The homepage may show it as a genuine permanent cut ("আগের দাম ১২ টাকা", "আগের চেয়ে প্রতি কেজিতে ২ টাকা কম"), and `/blog/vutta-silage-dam-koto-kothay-kinben` carries the one-line history. Rules the checker enforces: "আগের দাম" is an error unless the history has an earlier price; "ছাড় চলছে", "স্টক থাকতেই" and similar sale or urgency framing are always errors, because the price is the same all year; and the old price in any other form ("১২ টাকা কেজি", "৬০০ টাকা") is a superseded-price error unless wrapped in `<!-- price-history:start -->` / `<!-- price-history:end -->`. That last rule also catches a *delivered* price that happens to equal the old one, which a farmer could misread; write "কেজিপ্রতি ১২ টাকা পড়ে" instead.

## Data accuracy

- Feeding rates / prices must stay within published ranges (dairy 15–25 kg/day, beef 10–20 kg/day, goat/sheep 1–2 kg/day; concentrate ৪০–৫৫ টাকা/কেজি, silage ৮.৫০ টাকা/কেজি).
- Cite sources (DAERA, Teagasc) in a "তথ্যসূত্র" section when making factual claims. Do not invent savings/productivity numbers.
- **No invented customer stories.** We hold no permission-cleared customer quotes, so any "তারা বলেন" / "খামারিরা বলেন" / "সফল হয়েছেন" sentence is fabricated. State the mechanism instead, or use a real attributed quote. `npm run check` fails on these phrases.
- **The trust rules run on every public page and on `scripts/social-posts.json`, not only on articles.** Until 2026-09-29 the checker skipped every non-article page, which is how the homepage carried "কেন শত শত খামারি..." and "দ্রুত ডেলিভারি" for months. Beyond the phrase lists it now matches patterns (`TRUST_PATTERNS` in `scripts/check-site.mjs`): invented social proof, delivery-speed promises, health or yield promises ("গরু সুস্থ থাকে", "হজমশক্তি বাড়ায়"), absolute no-spoilage claims, brand superlatives, and the "তাজা খাবারের মতো পুষ্টি" nutrition equivalence. Describe the feed and the mechanism, not the result. A page that quotes a banned claim in order to disown it (`/about`'s "যে দাবিগুলো আমরা করি না") wraps that part in `<!-- trust:quoted-start -->` / `<!-- trust:quoted-end -->`. Two patterns are warnings only, pending the owner: the homepage reference price ("আগের দাম ১২ টাকা", "ছাড় চলছে") and "৯০% নির্ভুল".
- **No promised earnings.** Income depends on the reader's milk price, feed cost and animal, so never name a profit figure or write "লাভ করুন" / "আয় করুন" / "গ্যারান্টি". Link `/tools/dudher-labh-calculator` and let the farmer compute it. The checker fails on these too.
- **The homepage calculator's "খাদ্য খরচ সাশ্রয়" figure assumes ~3 kg silage replaces 1 kg concentrate** and prices the difference. That is a sound dry-matter equivalence (3 kg at ~30% DM is ~0.9 kg DM, as is 1 kg of concentrate at ~90%), and the assumption is disclosed under the number. It is still an *energy-only* substitution: concentrate also carries protein that silage does not, so silage cannot replace it one-for-one in practice, which is what `/blog/silage-vs-kacha-ghas-vs-khor#dry-matter` now tells readers. Treat the figure as the maximum, not the expected saving, and do not copy the framing onto new pages. `tools/silage-calculator` deliberately omits it.
- **No unsupported savings claims** ("cuts straw use in half"). State the price we actually charge, not the saving we imagine.
- Any article whose content changes materially should get its `dateModified` bumped; the checker rejects a `dateModified` earlier than `datePublished`.

## Accessibility

The audience is often older farmers on low-end Android phones, outdoors. A WCAG 2.1 AA audit (2026-09-29) set these rules:
- **Contrast at least 4.5:1 for text.** White on WhatsApp green `#25D366` is 1.98:1, so order buttons use `#0e7c4b` (hover `#0b6a3e`). The homepage greens moved from `rgb(20,148,91)` to `rgb(14,124,75)` and from `rgb(73,163,43)` to `rgb(53,122,31)`. Facebook blue is `#0b5fcc`, not `#1877F2` (4.2:1 on white). Form borders are `#6f8f7c` (3.6:1).
- **Bengali text at least 14px, body text 16px.** Conjuncts and matras blur below that on a cheap screen.
- **Touch targets at least 44px** (`min-h-11`) for buttons, chips, header links and FAQ summaries.
- **Global rules live in `css/src.css`:** `scroll-padding` so the sticky header and the fixed order bar never cover a focused link or an anchor target, spacing for footer links, placeholder colour, and a visible `:focus-visible` ring. Put a site-wide fix there rather than in 88 pages.
- **Toggle buttons carry `aria-pressed`,** in the markup and updated in JS. Colour alone does not tell a screen-reader user which animal is selected.

## Analytics (GA4)

- Measurement ID: `G-4SVWY8JWBX`. The homepage loads it inline; blog pages load `/js/ga.js`.
- All events fire through the `gaEvent(name, params)` helper.
- Event names are `snake_case` lowercase. Mark these as key events in GA4:
  - `whatsapp_click` — WhatsApp order CTA (**primary conversion**). Params: `link_location`, `link_url`, and on `/js/ga.js` pages also `page_path`.
  - `facebook_click` — Facebook link. Params: `link_location`, `link_url`, `page_path` (on `/js/ga.js` pages).
  - `link_location` values: the homepage derives them from the section heading (plus `floating_button` / `footer`); `/js/ga.js` pages use `header`, `article_body`, `sidebar`, `cta_section` or `footer`. Never hardcode a single value, it makes the report useless for comparing pages.
  - `phone_click` — a `tel:` link (the sticky bar, district pages, homepage). Params: `link_location`, `link_url`, `page_path` on `/js/ga.js` pages. Mark as a key event alongside `whatsapp_click`: a farmer who calls is the same lead. Both bootstraps must implement it; the checker asserts it.
  - `data-cta="<name>"` on a link or its wrapper overrides the derived `link_location` (both bootstraps), so two CTAs in the same region can be compared. In use: `hero`, `price`, `steps`, `bottom` (district pages), `sticky_bar`, `blog_index`. The homepage order form fires `whatsapp_click` with `link_location: order_form` itself, because it opens WhatsApp through `window.open` and no link listener sees it.
  - `video_play` — YouTube play. Params: `video_id`, `video_title`.
  - `calculator_use` — calculator inputs changed (debounced ~1.5s). Params: `animal_type`, `animal_count`, `duration_days`.
  - `calculator_order_click` — calculator → WhatsApp. Params: `animal_type`, `animal_count`, `duration_days`, `bags`.
  - `order_details_submitted` — order form → WhatsApp. Params: `submission_method`.
  - `article_view` — blog article loaded. Params: `page_title`, `page_path`.
  - `page_view` — non-article page loaded (e.g. blog index).
  - `ai_referral` — the visit landed from an AI assistant, detected from `document.referrer` or ChatGPT's `utm_source=chatgpt.com`. Params: `ai_source` (`chatgpt`, `perplexity`, `copilot`, `gemini`, `claude`, `meta_ai`, `you`), `page_path`, `page_title`. The source is kept in `sessionStorage` and **every later event in the session carries `ai_source`**, so a `whatsapp_click` can be attributed to the assistant that sent the farmer. Both bootstraps (`/js/ga.js` and the inline one in `index.html`) must implement this; the checker asserts the event name is present in both. In GA4, build a comparison on `ai_source` to see which guides AI engines actually cite.

## Editing Bengali text

- Some files mix precomposed and decomposed Bengali, so the same word exists as two different byte sequences and a find/replace silently edits only some occurrences. `npm run check` warns which files are not NFC-normalised. When editing one, normalise it first (`unicodedata.normalize("NFC", text)`) or match around the word with a regex wildcard.
- Content is Bengali with combining characters (e.g. য়, ড়, "সাশ্রয়"). Manual find/replace of Bengali often fails on encoding (precomposed vs decomposed). Prefer a Python script that matches ASCII anchors or uses `[^<]*` for the Bengali, rather than retyping Bengali into an edit tool.
- Keep `lang="bn"`. Homepage `font-hind` maps to "Noto Sans Bengali"; blog pages use "Hind Siliguri" — keep consistent with the file you're editing.

## Blog workflow

- **Writing a new guide: follow `.claude/skills/write-article/SKILL.md`.** It is the full procedure, and it exists because the same mistakes kept recurring: titles too long to render, the sidebar table of contents renumbered out of order, and new pages not registered in all five places. In Claude Code it loads as the `write-article` skill or the `/write-article` command; read the file directly if neither is available (skills register at session start, so a newly added one needs a restart).
- The five places a new page must be registered: `TAGS` in `scripts/related-guides.mjs` (throws if missing), one line in `llms.txt` plus the summary in `llms-full.txt` (checker warns), `scripts/social-posts.json`, a season's `guides` in `scripts/season-calendar.mjs` if seasonal, and `npm run build`.


- Copy `blog/article-template.html` for a new post (it has a body brand-reminder placeholder).
- After adding a post: run `npm run build:blog` (regenerates `blog/index.html` AND `sitemap.xml`), then add the article to `llms.txt` as one line (title + extensionless URL) and its summary to `llms-full.txt`.
- **Related guides are generated, not hand-picked.** `npm run build:related` (`scripts/related-guides.mjs`, part of `npm run build`) appends a "সম্পর্কিত গাইড" block to every article between `<!-- related-guides:start -->` and `<!-- related-guides:end -->`. It is idempotent: it strips its own previous block first. Relatedness comes from the explicit `TAGS` map in that script, and it prefers guides the article does not already link to, so the block opens new paths instead of repeating links already in the prose. **Adding an article means adding it to `TAGS`**, or the script throws. The same block ends with an "আপনার জেলায় সাইলেজ" strip linking every district page (read from `area/`, so a new district appears automatically): district pages convert best, and before this 34 of 38 articles linked none of them. The checker fails on an article whose block has no district links. The checker fails on an article without the block.
- Every post should carry `FAQPage` + `BreadcrumbList` JSON-LD alongside `Article` when it answers common farmer questions — AI assistants and Google pull answers from these.

## Free tools (tools/)

- `tools/*.html` are standalone free-tool pages: three calculators (`silage-calculator`, `dudher-labh-calculator`, `motatajakoron-khoroch-calculator`) and three print sheets (`khaddo-talika-chart`, `tika-krimi-calendar`, `hishab-khata`), plus `tools/index.html`.
- **`tools/ration-generator` is the least-cost ration formulator**, and the only tool with real logic behind it. The logic lives in `js/ration/` as dependency-free ES modules so it can be lifted into a standalone product later: `feeds.js` (24 feeds chosen from what Bangladeshi farm surveys show farms actually use, DM-basis nutrients from BLRI/BAU/SAU analyses with Feedipedia as fallback, 2024-2026 shop prices, safe inclusion caps per animal class, `avoidWhen` exclusions such as UMS in late pregnancy, `maxKgPerBW` caps, a `SOURCES` list rendered on the page), `requirements.js` (NRC 2001/2016/2007 + Kearl 1982: intake capacity and gut-fill floor, CP on mid-range intake, ME, Ca, P, minimum roughage), `lp.js` (two-phase simplex), `engine.js` (`formulate()`: goal-programming LP with penalised shortfalls so an impossible feed list still returns the best ration plus the reason, a soft energy ceiling at 115% so dry cows and goats are not fattened by the cheapest filler, a soft phosphorus ceiling at 0.5% of DM (`P_CEILING_PCT`; bran and oil cake carry 1-1.7% P, and before the ceiling the default 8 L cow ran at 0.71%, the NRC 2005 maximum tolerable level, which also forced 190 g of limestone to hold Ca:P; the page flags rations whose feed list cannot get under it), farm-step rounding, DCP/limestone top-up keeping Ca:P at least 1.3, custom feeds, and an honest "same feeds without silage" comparison from the same solver). `js/ration/package.json` sets `"type": "module"` so Node can import the same files. **`npm run test:ration` (`scripts/test-ration.mjs`) runs nine standard rations plus diagnosis, custom-feed, UMS and high-yield cases and is part of `npm run verify`.** `npm run build:ration` (`scripts/build-ration-tables.mjs`, part of `npm run build`) writes crawlable static tables into the page between `<!-- ration-tables:start/end -->` (requirements for standard animals, the full feed table with টাকা/MJ, example rations at default prices) and the sources between `<!-- ration-sources:start/end -->`, so search engines and AI assistants can read and cite the data without running JS, and the numbers cannot drift from the tool. The page passes the silage price in as `SILAGE_PRICE = 10` (the checker and `set-price` both key on that token). Silage's nutrient row is the Feedipedia maize-silage book value and the page says so, because `/about` promises we do not publish nutrition figures without a lab report. Market-quality findings baked into the defaults and worth knowing: rice bran (কুঁড়া) is the most-used concentrate (91% of farms) but market samples average ~8.8% CP because of husk mixing, so the default is the husk-mixed grade with auto rice polish as a separate feed; wheat bran tests 12.6-15.8% CP in Bangladesh (book 17%); market mustard cake has tested as low as 16% CP; ready feed labelled 10-18% tested 7.5-20.7%. Straw at 20-30 tk/kg (2024-25) is dearer per MJ than silage at 10, which is why the optimiser now often drops straw for milking cows; that is the arithmetic, not a bias. The tool must never show a savings or profit figure; it shows cost per litre and cost per kg gain, which are costs. The farmer's ticks, prices and custom feeds persist in `localStorage` (`kv_ration_v2`); the share button encodes them in the query string, which overrides the stored state. Owner's user data never leaves the browser.
- They are NOT scanned by the blog generator. When adding a tool: add its extensionless URL to `toolPages` in `scripts/generate-blog-index.mjs` (feeds sitemap), to the tools strip in that script's blog-index template, to `tools/index.html`, and one line to `llms.txt` plus a summary in `llms-full.txt`.
- `tools/silage-calculator` is the quantity calculator for the product itself (the homepage has one at `#calculator`, but an anchor cannot rank on its own). It reports daily kg, total kg, 50 kg bags, cost at the current price, cost per animal per day, and **how many days one bag lasts**, warning when that exceeds the 2-3 day open-bag limit. It deliberately shows no "savings" figure: see the note on the homepage calculator in Data accuracy.
- Calculators fire `calculator_use` / `calculator_order_click` with a `tool` param; print sheets fire `print_click` with `tool`. Silage price in calculator JS is the `PRICE` / `SILAGE_PRICE` / `PRICE_PER_BAG` constants, which `set-price` rewrites and the checker compares with `product.json`.

## AI discoverability (llms.txt / robots.txt)

- `/about` (`about.html`) is the trust page: who we are, where the silage is made, how it is sold, and a "যে দাবিগুলো আমরা করি না" section listing what we deliberately do not claim (nutrition figures without a lab report, customer quotes, earnings, delivery dates). Keep that section honest; it is the page's whole point, and it is what the trust rules elsewhere in this file look like when stated to the reader.
- **`llms.txt` is the short index; `llms-full.txt` holds the detail.** `llms.txt` (kept under 16 KB, the checker fails past that, because it had grown to 58 KB and many assistants truncate long files) carries the key facts in Bengali and English (price, cash on delivery, transport quoted per order on the confirmation call, WhatsApp, Bogura production base, no depots or dealers, all 33 district pages) and then one line per page: title plus absolute extensionless URL, no summaries. `llms-full.txt` carries the same facts plus a summary of every guide with its figures and sources, and every district URL. Update both whenever prices, delivery areas or the guide list change, **and update the `llms-full.txt` summary whenever an article is materially rewritten**: assistants decide whether to cite a guide from its summary, not from the page. The checker fails on any URL in either file that does not resolve or ends in `.html`.
- **The trust rules apply to `llms.txt` too.** It is quoted verbatim by assistants, so a promised profit figure or an invented testimonial there reaches farmers as ours exactly like one in an article, and nothing on the site would reveal it. The checker now runs the same banned-phrase, dash, digit and price checks over `llms.txt` and `llms-full.txt` (it had drifted: a "মাসিক ১৫-২০ হাজার টাকা লাভ করুন" line survived there for a claim no article ever made).
- `/blog/` ships an `ItemList` of every guide inside its `CollectionPage` JSON-LD (generated). That hands an assistant the whole library, titles and URLs included, from one block instead of 29 cards of markup.
- `robots.txt` explicitly allows AI crawlers (GPTBot, OAI-SearchBot, ClaudeBot, PerplexityBot, etc.). Do not add blanket Disallow rules.
